# 무투표 replay 실험 개요

## 목적

기존 모델과 2초 입력을 유지하면서 **판단 간격을 줄이면 더 빨리 소리를 감지할 수 있는지** 확인한다.
감지 시점뿐 아니라 미검출·오경보·모델 실행 비용을 함께 비교한다.

## 기존 실험과의 차이

| 실험 | 방법 | 확인 대상 |
|---|---|---|
| 기존 학습·정적 평가 | 2초 음원 하나를 분류 | 모델의 분류 성능 |
| S01·S02 | 저장된 예측 점수에 출력 임계값 적용 | 출력·보류 정책과 분할 안정성 |
| 이번 replay | 원음을 시간 순서대로 넣고 모델을 다시 실행 | 판단 간격에 따른 감지 시점과 비용 |

## 비교 조건

- 입력 길이 W: **2초 고정**
- 판단 간격 H: **2초 / 1초 / 0.5초**
- 출력 정책: **S0 즉시 출력 / S1 공통 임계값 / S2 라벨별 임계값**
- background 처리: v1.2의 세 가지 가정을 각각 비교한다. 실제 서비스 방식으로 확정한 것은 아니다.
- checkpoint·전처리·담당 라벨·무투표 최댓값 선택·S01 임계값은 유지한다.
- 데이터 경로: `D:\Sound_Dataset_aug`

## 진행 순서

1. 평가 group에서 라벨별 1개씩 **14개 원음으로 연결 점검**을 한다.
2. 원음 읽기, 전처리, 세 모델 로딩·추론이 정상인지 확인한다.
3. 원래 2초 음원이 온전히 들어간 window의 점수를 기존 저장 예측과 대조한다.
4. 연결이 확인되면 평가 음원을 늘려 감지 시점·미검출·오경보·실행 비용을 비교한다.

## 범위와 한계

- 이번 단계는 **재학습이나 모델 내부 가속 실험이 아니다.** Early exit·짧은 문맥 학습·라벨 재배정은 후속 실험이다.
- episode는 **2초 무음 + 기존 음원 2초 + 2초 무음**으로 구성한다.
- 측정 기준은 음원 삽입 시점이다. 실제 사건 onset이나 화면 표시 지연을 측정한 결과가 아니다.
- 최초 14개는 연결 점검용이며 정책 성능을 확정하는 표본이 아니다.
- 판단 간격 단축은 실행 횟수를 늘린다. 모델 한 번의 연산 시간이 줄어드는 것은 아니다.
- 제공된 predefined/0.70 모델을 사용하는 참고 실험이며, 과거 최고 성능 무투표 run의 재현으로 확인된 상태는 아니다.

자세한 명령은 [실행 순서](README_실행순서.md)를 따른다.
