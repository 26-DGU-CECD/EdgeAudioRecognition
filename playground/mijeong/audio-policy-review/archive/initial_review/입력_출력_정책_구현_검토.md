# 기존 구현에 기반한 입력·출력 정책 설계 및 논문 조사

작성일: 2026-10-15  
범위: 모델 내부 계층화 제외 / 비학습형 실행 정책 / 기존 ensemble 보존

## 1. 결론과 확인 범위

기존 구조에 바로 연결할 1차 방법은 **2초 입력 유지 → 겹침 구간 실행 → 기존 클래스별 가중 fusion → 라벨별 출력 상태기**다.

현재 파일에서 확인한 specialist는 “담당 라벨만 출력하는 모델”이 아니다. 각 모델이 **13개 사건 + background의 14개 logits**를 출력하며, 전문 클래스 지정은 학습 데이터의 유지 비율과 fusion 가중치에 반영된다. 따라서 기존 정책 설계에서 specialist의 최고 담당 라벨끼리만 비교하던 가정은 수정해야 한다.

분석 대상은 사용자가 제공한 두 폴더의 합집합이다. 두 폴더는 한 프로젝트를 나눠 담은 파일 구성으로 보인다. 원본 소스·모델·결과는 변경하지 않았다. 저장된 logits를 NumPy로 분석했으며, 학습이나 모델 추론을 새로 실행하지 않았다.

이 자료에서 학습·정적 평가·오프라인 fusion은 확인했다. 사용자가 앞서 설명한 실제 시스템의 비동기 실행과 2초 갱신은 요구조건으로 유지하되, 해당 런타임 코드와 보드 실측 자료는 제공된 폴더에서 확인하지 못했다. 미제공 런타임까지 미구현이라고 단정하지 않는다.

## 3. 기존 fusion을 유지해야 하는 이유와 수식

모델 m의 14클래스 softmax를 p_m(c), 클래스별 F1을 F1_m,c라 한다.

현재의 원 가중치:

a_m,c = max(F1_m,c, 0.05)^2 × expert_boost_m,c

전문 모델에는 expert_boost=1.25, 나머지는 1을 적용하고, 클래스별로 정규화한다.

w_m,c = a_m,c / Σ_m a_m,c

그다음:

r(c) = Σ_m w_m,c p_m(c)  
P(c) = r(c) / Σ_j r(j)  
c* = argmax_c P(c)

같은 클래스라도 세 모델 모두 기여한다. 예를 들어 분석에 사용한 F/nonexpert_070의 gun 가중치는 EfficientAT 약 0.500, YAMNet 0.220, MobileNetV4 0.280이다.

EfficientAT의 gun 점수 하나를 바로 최종 출력하면 현재 F fusion과 다른 방법이 된다. 또한 비전문 데이터를 줄이는 것은 학습량 조절이며, 같은 backbone을 실행하는 추론 비용이 그 비율만큼 줄어든다는 뜻은 아니다.

현재 재분류·기준값 실험에서는 기존 가중치를 먼저 동결한다. 가중치 변경은 별도 비교군으로 둔다.

## 4. 논문 조사: 무엇을 어디에 적용하는가

### R1. 클래스별 기준값 최적화

**Cances, Guyot, Pellegrini — WASPAA 2019**  
*Evaluation of Post-Processing Algorithms for Polyphonic Sound Event Detection*

논문은 시간별 음향 점수의 smoothing·absolute threshold·hysteresis 등과 클래스 공통/개별 파라미터를 비교한다. 이번 적용은 **클래스별 출력 임계값·확인 시간 탐색**이다. 원 연구는 사건 구간 추정이고 일부 결과에는 정답 audio-tag 조건이 있으므로, 수치를 현재 온라인 성능으로 옮기지 않는다.  
[논문](https://arxiv.org/pdf/1906.06909) / [출판 정보](https://ieeexplore.ieee.org/abstract/document/8937143/)

### R2. 진입·유지·해제 분리

**Dinkel & Yu — ICASSP 2020**  
*Duration Robust Weakly Supervised Sound Event Detection*

고정 median filter의 짧은 사건 편향을 분석하고 높은·낮은 두 임계값으로 구간을 구성한다. 원 논문의 high=0.75, low=0.2는 그 실험의 값이다. 적용은 **높은 기준으로 진입하고 낮은 기준으로 유지하는 원리**다. 앞뒤 구간 확장을 실시간에 맞춰 causal 상태기로 바꾸는 것은 본 프로젝트의 확장이다. 과거 onset을 복원해도 실제 알림 시간은 앞당겨지지 않는다.  
[논문](https://arxiv.org/pdf/1904.03841)

**Dinkel, Wu, Yu — IEEE/ACM TASLP 2021**  
*Towards Duration Robust Weakly Supervised Sound Event Detection*

clip-level gate와 frame-level double threshold를 결합한다. 현재 head는 2초 clip-level 14 logits이므로 triple threshold를 그대로 구현할 수 없다. 원 모델의 frame head를 추가하는 것은 이번 “정책 변경 중심” 단계에 포함하지 않는다.  
[논문](https://arxiv.org/pdf/2101.07687)

### R3. 점수 사후 보정

**Guo et al. — ICML 2017**  
*On Calibration of Modern Neural Networks*

신경망 확신도와 정답률의 불일치를 분석하고 temperature scaling을 평가한다. 기존 14클래스 fusion의 최종 점수에 대해 다음 보정 후보를 적용한다.

Q(c) = softmax(log(P(c)) / T)

T>0이면 라벨 순위가 유지되어 기존 top-1을 보존하면서 확정 임계값을 다시 설정할 수 있다. T는 별도 보정 자료에서 NLL로 선정한다. 이는 원 논문의 개별 신경망 logits 보정을 최종 fusion에 적용하는 확장이다. 학습형 행동 정책은 없지만 데이터로 파라미터를 fitting한다. 보정이 항상 좋아지는 것은 아니므로 T=1 대조군을 유지한다.  
[논문](https://proceedings.mlr.press/v70/guo17a.html)

현재 모든 head가 공통 14클래스를 출력하므로 앞서 우려했던 “서로 다른 담당 클래스만의 softmax” 문제는 확인 코드에는 해당하지 않는다. 그러나 서로 다른 confidence의 calibration 문제와 운영 분포 변화는 남는다.

### R4. 미확정과 coverage

**Geifman & El-Yaniv — NeurIPS 2017**  
*Selective Classification for Deep Neural Networks*

기존 모델의 confidence로 출력을 거부하며 출력 오류와 coverage를 다룬다. 적용은 **top-1은 정하되 조건 미충족이면 미확정**이다. 학습형 reject head를 추가하는 SelectiveNet과 구분한다. 거부율을 높인 정답률만 보고하지 않고 전체 사건의 올바른 출력 비율을 함께 평가한다.  
[논문](https://proceedings.neurips.cc/paper/2017/hash/4a8423d5e91fda00bb7e46540e2b0cf1-Abstract.html)

### R5. 추가 관찰의 종료 규칙 보정

**Ringel et al. — ICML 2024**  
*Early Time Classification with Accumulated Accuracy Gap Control*

충분한 관찰에서는 맞지만 조기 판단에서는 틀리는 사례를 통제하고, 이른 종료 사례에 오류가 몰리는 문제를 다룬다. 적용은 **새 입력으로 갱신되는 fused score 시퀀스의 관찰 종료 기준**이다. 내부 층 종료나 모델의 실행 주기를 직접 최적화하는 방법은 아니다.

본 프로젝트에서는 사건·배경 에피소드의 시작/끝 정의, 미확정, rolling window, 단일 표시 경쟁을 추가 설계해야 한다. i.i.d. 보정 사례 등의 가정이 필요하며 겹친 창이나 증강 clip을 독립 사례로 간주하지 않는다. 현재 NPZ만으로는 관찰 시간별 시퀀스가 없어 직접 재현할 수 없다.  
[논문](https://proceedings.mlr.press/v235/ringel24a.html) / [원문](https://arxiv.org/pdf/2402.00857)

### R6. 여러 파라미터를 함께 선택

**Laufer-Goldshtein et al. — ICLR 2023**  
*Efficiently Controlling Multiple Risks with Pareto Testing*

다목적 후보 탐색과 독립 데이터의 위험 검사를 결합한다. 적용은 **hop·임계값·확인 시간·출력 대기 조합을 고르고 제약을 검증하는 절차**다. 원 논문의 층/헤드 pruning은 도입하지 않는다.  
[논문](https://arxiv.org/abs/2210.07913) / [공식 코드](https://github.com/bracha-laufer/pareto-testing)

**Angelopoulos et al. — Annals of Applied Statistics 2025**  
*Learn then Test: Calibrating Predictive Algorithms to Achieve Risk Control*

모델 재학습 없이 파라미터화된 규칙을 다중 가설검정으로 보정한다. 현재 단일 cutoff 탐색보다 넓은 정책 설정 검증에 참고한다. 원고 초기 버전은 2021이며 정식 출판 연도는 2025다.  
[논문](https://arxiv.org/abs/2110.01052) / [출판 DOI](https://doi.org/10.1214/24-AOAS1998)

**Zecchin, Park, Simeone — ICML 2025**  
*Adaptive Learn-then-Test: Statistically Valid and Efficient Hyperparameter Selection*

후보 검사의 데이터 사용을 효율화하는 확장이다. 다수 설정 탐색 비용이 커질 때의 선택 사항이며 필수 첫 구현은 아니다.  
[논문](https://proceedings.mlr.press/v267/zecchin25a.html)

일반 ML top-tier 근거와 직접적인 음향 후처리 근거를 함께 사용한다. 논문의 보장·최적값이 현재 음향·하드웨어 환경에 자동 적용된다고 주장하지 않는다.

- 분석은 validation만 사용했다. test 숫자는 아래의 기존 실험 현황 기술에만 사용한다.

fire_alarm은 이번 탐색 범위와 최소 출력 수 조건에서 95%를 달성하는 후보가 없었다. 보편적인 불가능성이 아니라 현재 fusion과 데이터에서의 결과다. 임계값만 높이면 해결된다고 가정하지 않는다.

dog_bark·scream은 추가 cutoff=0에서도 탐색 조건을 만족했다. 무조건 출력해도 된다는 뜻이 아니다. 전체 14클래스의 top-1 조건은 유지되며 독립 데이터 검증도 필요하다.

knock은 126 clip이지만 기록된 원본 group은 14개뿐이다. 126개의 독립 시험으로 해석한 신뢰성 주장은 피한다.

> 탐색값은 실기 config에 넣을 확정값이 아니라, 현재 모델에 맞게 후보 범위를 좁히기 위한 값이다.

## 6. 입력 정책: 어떤 소리를 언제 실행할 것인가

### 6.1 1차 구현은 2초 입력 유지

현재 입력은 32,000 samples다. 연속 오디오의 ring buffer에서 최신 2초를 잘라 현재와 같은 전처리 후 세 모델에 전달한다.

학습 clip 길이 변경이나 YAMNet mean pooling을 max로 바꾸는 것은 별도 입력·모델 실험이다. 우선 입력·fusion을 보존해 실행 주기 변경의 효과를 확인한다.

현재 파일 loader는 긴 파일의 선두 2초를 사용한다. 온라인에서는 최신 2초를 먼저 잘라야 한다. 긴 녹음을 현재 loader에 넣는 것만으로 streaming 평가가 되지 않는다.

### 6.2 실행 간격 H의 초기 후보

| 파라미터 | 기준·후보 | 선정 절차 |
|---|---|---|
| 문맥 W | 초기 2.0초 고정 | 현재 32,000 samples 유지 |
| 실행 간격 H | 2.0 / 1.0 / 0.5 / 0.25초 | 실제 장치·3모델 동시 운용·batch=1 측정 |
| 최초 버퍼 충족 | 2초 | 시작 시 warm-up을 평상시 지연과 구분 |
| 입력 시각 | sample index 기준 | 처리 완료 시각과 분리 |
| 모델별 대기 큐 | 초기 최신 요청 한 개 | 적체 감소와 짧은 사건 누락 동시 평가 |

H=0.5초라면 2.0, 2.5, 3.0초에 각각 [0,2], [0.5,2.5], [1,3]초를 입력한다. 긴 문맥을 유지하면서 판단 기회를 늘리는 방법이다. 이것이 충분한 사건 정보 확보나 정확한 검출을 보장하지는 않는다.

학습 batch_size=40 시간과 runtime batch=1 시간은 다르다. 저장된 YAMNet embedding에서 head만 실행하는 시간을 실제 새 음성의 전체 처리시간으로 사용하지 않는다.

너무 짧은 H는 frontend 재계산과 큐 적체를 늘릴 수 있다. 처리시간과 skip 수를 모두 측정하고, 처리 능력을 초과하는 후보는 제외한다.

### 6.3 전처리 변경과 실행 정책 변경을 분리

현재 high-pass는 각 clip에서 filter 상태를 초기화한다. 연속 stateful IIR로 바꾸면 경계 처리가 달라진다. 우선 현재 window별 처리 재현을 기준으로 두고, 연속 filter를 별도 평가한다.

RMS 정규화는 window 전체를 사용한다. window가 이동하면 gain이 바뀔 수 있어 과거 patch embedding의 단순 재사용이 현재 재계산과 같다고 가정하지 않는다.

-30 dBFS를 추론 생략 hard gate로 사용하는 것은 새로운 변경이다. 작은 위험음의 미검출을 확인하고 적용한다. 현재 NPZ에는 RMS가 없어 원음 재계측이 필요하다.

STFT center 설정도 정책 단독 비교에서는 유지한다. 이미 획득한 window 내부의 padding과 미획득 미래 음성 사용을 구분한다.

## 7. 출력 정책: 라벨별 고정 상태기

### 7.1 전체 14클래스 top-1과 background 처리

각 window에 기존 fusion을 적용하고 c*=argmax P(c)를 구한다.

1. c*=background이면 다른 foreground를 강제로 표시하지 않는다.
2. foreground top-1이면 해당 라벨의 확정 조건을 검사한다.
3. 조건 부족이면 새 입력으로 다시 판단하거나 미확정 처리한다.
4. 조건을 통과하지 못한 최고 후보 대신 낮은 후보를 표시하는 규칙은 별도 실험으로 분리한다.

background는 모델의 배경 판정이고, 미확정은 근거·결과 부족이다. 두 내부 상태를 구분한다.

### 7.2 파라미터와 설정 방법

| 값 | 의미 | 지정 방법 |
|---|---|---|
| T | 최종 fusion의 temperature | 보정 데이터에서 NLL 최소화, T=1 비교 |
| τ_fast,c | 새 결과 한 번으로 후보 제출하는 높은 값 | 정적 후보 탐색 후 연속 단발 오경보 검증 |
| τ_on,c | 일반 확인을 시작하는 값 | 라벨별 출력 정답률·올바른 출력 비율로 후보 생성 |
| n_on,c | 확인에 필요한 새 window 결과 수 | 초기 1/2/3 후보, 시간 trace 재생 |
| τ_off,c | active 유지에 사용하는 낮은 값 | 단절·과도한 유지 평가 |
| d_off,c | 낮은 점수가 지속돼야 하는 해제 시간 | 재알림 분단과 해제 지연 비교 |
| τ_bg | 선택적인 추가 background 거부 기준 | background top-1 기본 규칙에 대한 추가 효과 평가 |
| max_age | 결과 사용 기한 | window_end·H·실측 지연에 맞춰 설정 |
| d_arb | 미도착 모델을 기다리는 추가 시간 | fusion 불일치·표시 지연 비교 |

일반적으로 τ_off < τ_on ≤ τ_fast로 제약을 둔다. score 보정 방법이 바뀌면 임계값도 다시 설정한다.

n_on=2는 독립 음향 증거 두 개를 뜻하지 않는다. 동일 score의 반복 조회나 한 window의 세 모델 도착을 시간적 확인 세 번으로 계산하지 않는다. 새로운 window의 관찰 결과에서만 확인 상태를 갱신한다.

### 7.3 실행 규칙 예

- q(c*)≥τ_fast,c*: 빠른 확정 경로.
- τ_on,c*≤q(c*)<τ_fast,c*: 다음 새 window 결과에서 같은 후보의 지지를 확인.
- n_on을 충족: 후보 제출.
- 후보 변경·근거 저하: 확인 상태 갱신 또는 초기화.
- active 라벨: τ_off와 d_off로 유지·해제 관리.
- 미도착·만료 결과: 음성 관측으로 대체하지 않음.

충격음에는 긴 연속 확인을 요구하지 않는 가설을 두고, 지속·반복음은 추가 확인의 효과를 비교한다. siren도 충분히 뚜렷하면 빠른 경로를 사용한다. 입력에 따라 행동은 달라지지만 결정 규칙은 고정이다.

### 7.4 사건 상태와 화면 유지 시간 구분

짧은 사건을 사용자가 읽을 수 있도록 화면에 유지하는 시간과 detector의 active 상태는 다르다. 최고 후보가 변했는데 오래된 화면을 유지하면 “현재 최고 후보 하나”와 충돌할 수 있다. 초기에는 새 확정 후보로 바꾸는 단순 정책을 검증하고 표시 유지를 별도 설정으로 둔다.

과거 2초 창 안에 사건이 남으면 실제 종료 후에도 score가 높을 수 있다. clip score로 정확한 offset을 보장하지 않는다. 해제와 재알림 조건은 연속 데이터로 결정한다.

## 8. 비동기 fusion의 출력 대기 정책

### 8.1 기준 경로

같은 window_id를 세 모델이 비동기로 처리하고 전부 도착하면 기존 fusion을 계산한다. 실행은 비동기지만 출력 대기는 존재한다. 먼저 이 경로가 저장된 offline fusion과 동일한지 확인한다.

- window_id·sample 구간·전처리 버전을 공유한다.
- 14 logits 전체를 전달한다.
- 오래된 결과가 최신 상태를 덮어쓰지 않도록 한다.
- 미도착 결과를 확률 0으로 채우지 않는다.
- 서로 다른 window의 score 혼합은 별도 정책으로 평가한다.

### 8.2 기존 fusion에서 도출한 순위 보장 확장

이 방법은 본 프로젝트의 가중 fusion에서 직접 도출한 추가 설계다. 특정 논문의 알고리즘 재현이나 층 기반 early exit으로 표현하지 않는다.

같은 window에서 도착한 모델을 R, 미도착 모델을 M이라고 한다.

L_c = Σ_(m∈R) w_m,c p_m(c)  
U_c = L_c + Σ_(m∈M) w_m,c

미도착 softmax는 0~1 범위이므로 최종 미정규화 점수 r(c)는 [L_c,U_c] 안에 있다.

어떤 c*가 다음을 만족하면:

L_c* > max_(j≠c*) U_j

미도착 모델이 어떤 결과를 반환해도 기존 최종 argmax는 c*다. background도 비교에 포함한다. 마지막 공통 정규화는 순위를 바꾸지 않는다.

**이는 최종 fusion과 같은 라벨이라는 보장이지 정답 보장이 아니다.** 동일 입력 window와 고정 가중치가 필요하며, 서로 다른 시각의 score에는 적용하지 않는다.

정규화 score의 보수적 하한도 다음처럼 만들 수 있다.

Z_upper = Σ_j L_j + Σ_(m∈M) max_j w_m,j  
P_lower(c*) = L_c* / Z_upper

순위 조건과 P_lower≥τ를 동시에 만족하면 최종 fusion도 해당 cutoff를 통과한다. 이 식은 T=1 기준이며 보정 후 q의 하한으로 그대로 사용하지 않는다.

### 8.3 저장된 validation으로 확인한 결과

F/nonexpert_070의 23,847 clip에 대해 미도착 모델의 실제 score를 보지 않고 bound로 판단했다.

| 도착한 결과 | 전체 clip 중 최종 top-1 확정 가능 비율 |
|---|---:|
| EfficientAT 한 개 | 0% |
| YAMNet 한 개 | 0% |
| MobileNetV4 한 개 | 0% |
| EfficientAT + YAMNet | 68.67% |
| EfficientAT + MobileNetV4 | 63.20% |
| YAMNet + MobileNetV4 | 41.81% |

확정된 모든 사례는 세 결과를 사용한 최종 argmax와 일치했다. 비율에는 background가 포함되며 foreground 정답률이 아니다.

P_lower≥0.75를 추가로 요구한 foreground 조기 확정은 모든 조합에서 0건이었다. 보수적 bound와 높은 cutoff를 결합하면 이득이 사라질 수 있다.

현재 NPZ에는 도착 시간과 순서가 없어 몇 ms를 줄이는지는 미측정이다. 이미 시작한 모델을 계속 계산한다면 계산량은 줄지 않는다. 줄이려는 대상은 마지막 결과를 기다리는 시간이다.

## 9. 추가 관찰 종료의 통계적 보정

현재 NPZ는 각 2초 파일의 결과 한 개다. 파일 순서를 이어 붙여 온라인 관찰 시퀀스로 취급하지 않는다.

Ringel 방식 적용 전 다음을 구축한다.

- 독립 녹음 session과 사건·배경 episode.
- 사건 onset/offset.
- 실행 H에 따른 같은 window의 모델별 score.
- 실제 결과 도착·출력 시각.
- 추가 관찰·확정 정책을 재생한 trace.

논문의 gap은 충분한 관찰의 정답을 조기 판단에서 잃는 경우다. full 모델에서도 틀리는 사건을 제어하지 않으므로 절대적인 위험음 recall과 오경보 제약을 함께 둔다.

기존 validation은 모델 선택·전문 배정·fusion weight 산출에 이미 쓰였다. 이를 나중에 나누는 것만으로 독립 보정 조건을 충족한다고 단정하지 않는다. 새 holdout/session을 마련하거나 개발 전체 split을 다시 설계한다.

H가 짧으면 판단 횟수와 우연한 높은 score의 기회도 늘 수 있다. H=2초에서 만든 cutoff를 단축 H에서 검증 없이 운영하지 않는다.

| 대상 | 현재 상태 |
|---|---|
| 입력 W·sample rate | 2초·16 kHz를 기준으로 유지 가능 |
| 전처리 값 | 80 Hz/-30 dBFS/-20 dBFS 구현값 확인 |
| fusion weight | 기존 CSV를 읽어 고정 가능 |
| 정적 cutoff 후보 | validation에서 탐색 완료, 채택에는 독립 검증 필요 |
| H | 실제 장치의 전체 처리시간 필요 |
| n_on/d_off | 연속 score trace 필요 |
| 순위 조기 확정 조건 | 수식 도출 및 저장 score에서 일치 검증 |
| 순위 확정의 시간 이득 | 모델별 비동기 도착 로그 필요 |
| 관찰 종료의 통계 보장 | 독립적인 시계열 보정 episode 필요 |
| 시간당 오경보·2초 내 검출률 | 현재 clip NPZ에서 계산 불가 |

논문 근거로 기준값을 지정한다는 것은 원 숫자를 옮기는 것이 아니라, **현재 score로 후보를 만들고 관찰·실행·출력을 재생해 선택한 뒤 독립 데이터에서 확인하는 절차**를 구현하는 것이다.

## 13. 이어서 필요한 자료

- 실제 오디오 수집·2초 실행·비동기 결과 수신·화면 표시 코드.
- Linux metadata가 가리키는 원음 또는 연속 녹음.
- onset/offset과 background 구간 annotation.
- Raspberry Pi 5/Orin Nano의 batch=1 전체 처리시간.

위 자료 확보 전에도 고정 입력의 fusion 재사용, 정적 cutoff 후보 분석, packet 설계까지 진행할 수 있다. 추가 관찰 시간과 실행 H는 최적화 완료값으로 표현하지 않는다.
