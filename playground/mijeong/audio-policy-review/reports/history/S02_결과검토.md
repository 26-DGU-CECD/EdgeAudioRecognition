## 결론

S02의 다섯 seed 결과가 모두 생성되었고, seed 42의 전체 비교 결과는 S01과 일치했다.
다섯 실행의 설정은 seed와 그에 따른 분할·임계값을 제외하면 같고, 입력 예측 파일 hash도 같다.
metadata의 기록된 group_id로 분할을 재계산했을 때 보정·평가 clip/group 수가 설정과 일치했고, 각 실행 안의 group 중복은 0이었다.

현재의 95% 보정 정밀도 목표에서 라벨별 S2를 기본 출력 정책으로 채택할 근거는 부족하다.
S1도 사건 정답 출력률이 낮고 fire_alarm을 거의 출력하지 못하므로 배포 정책으로 확정한 결과가 아니다.

## 비교 범위

저장된 validation 예측에 대한 출력 정책 분석이다. 신규 학습, 원음 추론, GPU 측정은 수행하지 않았다.
실제 원음 데이터셋의 Windows 경로와 파일 접근 가능 여부는 여전히 확인되지 않았다.
metadata에 기록된 과거 원음 루트는 `/home/plass/YAMNet/aug_data`이다.

아래 표는 background=global_max라는 처리 가정 안의 비교이며, 실제 서비스의 background 구현으로 확인된 것은 아니다.
각 수치는 다섯 seed 결과의 단순 평균이다. 서로 겹치는 validation 재분할이므로 독립 실험 5회나 최종 test로 해석하지 않는다.
성능 비율은 원본 group을 동일 가중한 비율이 아니라 코드가 집계한 clip 단위 지표다.

## 다음 진행

1. S01/S02를 정적 정책 탐색 결과로 보존한다. 다음 실험을 위해 유리한 seed를 고르거나 임계값을 운영값으로 확정하지 않는다.
2. 실제 원음 데이터셋의 Windows 루트와 원본 녹음/증강 파일 구성을 확인한다.
3. 기존 metadata 경로를 보존하고, 별도 경로 매핑으로 원음 존재 여부·열기·길이·sample rate를 점검한다. 저장 예측과 연결하는 path 식별자를 먼저 덮어쓰지 않는다.
4. 저장 예측으로 세 모델 각각의 fire_alarm/siren 혼동과 담당 라벨 점수를 비교한다. 원음이 확보되면 오답 원본 group을 골라 청취하고 라벨·전처리·음원 품질을 점검한다.
5. 실제 최고 성능 무투표 기준의 checkpoint, 점수 변환, background 처리 규칙을 확정한다. 현재 실행은 제공된 predefined/0.70 모델의 참고 실험이다.
6. 무투표 selection 설정을 사용하는 replay 연결을 구현한 뒤 W=2초, H=2/1/0.5초를 비교한다. 기존 replay는 가중 voting 경로이므로 그대로 연결하지 않는다.
7. onset 주석과 실제 표시 시각이 있는 별도 연속 녹음으로 2초 내 정답 출력률·미검출·시간당 오경보를 평가한다.
