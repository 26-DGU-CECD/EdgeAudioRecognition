## 무엇을 비교하는가

기존 specialist checkpoint·담당 라벨·전처리·2초 입력을 유지하고, 결합 F·출력 확정 R·갱신 간격 I·시간 확인 T·다른 모델 결과 대기 A를 순서대로 비교한다.
새 모델 학습, RL, 정책 신경망, 모델 내부 early exit는 현재 단계에 없다.

| 축 | 비교군 |
|---|---|
| F 결합 | F0 담당 라벨 max / F1 평균 soft voting / F2 클래스별 가중 soft voting |
| R 출력 확정 | R0 즉시 / R1 공통 임계값 / R2 라벨별 임계값과 명시적 recall backoff |
| I 실행 간격 | I0 2초 / I1 1초 / I2 0.5초 / I3 완료된 결과에 따른 0.5·1초 적응 |
| T 시간 확인 | T0 즉시 / T1 같은 후보 2회 / T2 단발·강한 후보와 일반 후보 차등 확인 |
| A 결과 대기 | wait_all 전체 수집 / bounded 동일 voting 판단을 확정할 수 있을 때 조기 출력 |

R2는 recall을 보존하려고 precision 조건을 완화할 수 있는 새 비교군이다. 항상 precision 95%와 recall 50%를 만족하는 방법이 아니다.
F2 가중치는 fusion-fit에서 새로 계산하고, R 임계값은 별도 policy-fit에서 계산한다.
따라서 S01/S02의 S1/S2 수치와 일대일로 비교하지 않는다.

## 3. A 단계: 저장 점수로 결합·확정 정책 비교

```powershell
python run_framework_pilot.py `
  --project-root "$pilotProject" `
  --assignment predefined --ratio 0.70 `
  --seed 42 --fusions F0 F1 F2 `
  --owner-background global_max `
  --target-precision 0.95 --minimum-accepted 20 --recall-floor 0.5 `
  --out "$pilotOut"
```

F0/F1/F2 × R0/R1/R2 = 9개 정적 결과가 생성된다.

| 결과 파일 | 확인할 항목 |
|---|---|
| framework_static_comparison.csv | 출력 정밀도, 사건 정답 출력률, 배경 오출력률, macro F1, below_recall_floor_labels |

모든 threshold_source를 목표 충족으로 해석하지 않는다. backoff·shared·upstream 상태와 평가 라벨별 recall을 함께 확인한다.

## 11. D 단계: 다른 모델 결과를 기다리는 시간 비교

F1 또는 F2, 고정 I, T0에서만 실행한다. F0·I3·T1/T2는 bounded와 조합하지 않는다.
아래 F1은 비교용 예시이며 최종 채택 결론이 아니다.


early_certified_windows, total_early_wait_saved_s, 미검출·오출력, superseded_output_windows를 함께 확인한다.
동일 voting의 라벨·확정 여부를 먼저 알 수 있는지 보는 실험이며 모델 job은 취소하지 않는다.
추론 FLOPs나 실제 공유 GPU 시간이 줄었다고 해석하지 않는다.

## 12. 결과 읽기와 다음 검증

각 result-tag마다 comparison.csv, per_episode.csv, trace.csv, scope.json이 생성된다.

| 항목 | 의미 |
|---|---|
| hit_by_clip_2s / missed_by_clip_2s | 삽입 후 2초 안의 정답 표시 비율과 놓친 수 |
| first_correct_s_p50/p95_detected_only | 검출된 episode만의 첫 정답 시간. 미검출과 함께 읽음 |
| wrong_label_episode_rate | 삽입 음원과 겹치는 입력창에 대한 오표시 episode 비율 |
| background_episode_alert_rate | background 삽입 음원과 겹치는 입력창에 대한 알림 비율 |
| synthetic_prefix_any_alert | per_episode/trace에서 삽입 전 무음 구간의 알림을 별도로 확인 |
| scheduled_model_calls | 정책이 요청한 모델 호출 수 |
| display_changes / nonempty_label_switches | 표시 변경과 사건 라벨 간 교체 |

비교표의 background_episode_alert_rate가 합성 episode 전체의 모든 오알림을 포함하는 것으로 해석하지 않는다.
audio_clock은 연산·큐 시간을 제외한다. independent_worker_sim은 단독 서비스 시간으로 계산한 FIFO 모의실험이다.
CPU YAMNet과 GPU Torch를 사용하는 이번 Windows run은 세 모델 GPU 동시 처리시간 실험이 아니다.
실제 사건 onset→2초 이내 올바른 표시 목표는 onset 주석이 있는 독립 연속 음원과 실제 장치·동시 worker·표시 로그로 별도 검증한다.
이번 단계에서 임계값·fusion weight를 test 결과로 재조정하지 않는다.

## 실행 중단 기준
