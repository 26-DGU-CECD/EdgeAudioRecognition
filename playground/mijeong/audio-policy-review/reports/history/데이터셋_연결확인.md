사용자가 알려준 **C:\Users\PLASS\Desktop\alarm_aug_dataset**도 확인했지만, 기존 metadata와 파일명/상대 경로가 일치하지 않았다.
두 폴더가 원천 데이터와 증강 결과의 관계인지는 생성 이력이 없어 아직 확인하지 않았다.

각 폴더당 클래스별 사전순 앞의 2개 파일을 점검했다. 확인한 샘플의 최초 2초 값은 모두 유한했다.
D:의 샘플은 유효한 IEEE float WAV였다. Python 표준 wave 모듈이 이 형식(code=3)을 지원하지 않는 것을 파일 손상으로 해석하지 않고, RIFF 헤더와 float sample을 직접 읽어 확인했다.
샘플 점검은 전체 데이터의 디코딩 건전성·정답 라벨·사건 onset 확인을 대신하지 않는다.

## 경로 연결

현재 metadata에 기록된 경로:

```text
/home/plass/YAMNet/aug_data/<class>/<filename.wav>
```

연결이 확인된 로컬 경로:

```text
D:\Sound_Dataset_aug\<class>\<filename.wav>
```

파일명만으로 매칭하지 않는다. 기존 metadata 13,770개 행의 파일명은 D: 데이터 안에서 둘 이상 존재한다.
클래스 폴더를 포함한 상대 경로로는 전체 238,388개가 일치했다.

원본 metadata, class_names, checkpoint, S01/S02 결과는 변경하지 않았다.
metadata의 SHA-256도 점검 전후 동일하다.
과거 Linux 원음의 내용 hash가 없으므로 당시 오디오와 byte 단위로 동일하다는 검증은 수행할 수 없었다.

## 다음 코드 작업

1. 기존 path 식별자를 유지한 채 파일을 읽을 때 위 루트만 치환하는 오디오 로더를 연결한다.
2. validation evaluation group에서 라벨별 1개씩 원음을 골라 전처리·모델 로딩을 점검한다.
3. `fire_alarm`/`siren`을 우선 확인하고, 무투표 selection 규칙으로 동일 window 결과를 평가한다.
4. 모델 입출력 연결이 확인되면 2초 문맥에서 hop=2/1/0.5초를 비교한다.

이 문서 작성 단계에서는 신규 모델 학습이나 추론을 실행하지 않았다.
현재 `prepare_replay.py`, `export_replay_predictions.py`, `evaluate_replay.py`는 가중 voting용 설정에 연결되어 있으므로 무투표 실험용 연결 수정이 필요하다.
`config.py`의 DATASET_ROOT만 바꿔도 metadata에 저장된 Linux 절대 경로가 자동 변환되는 것은 아니다.
