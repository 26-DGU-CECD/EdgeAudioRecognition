## 판단

정적 비교와 원음 연결 점검은 완료됐다. F2·R0·1초 간격(I1)은 다음 확대 실험의 유력한 탐색 후보다. 최종 채택 결론은 아니다. F1도 비교군으로 유지한다.

정적 평가는 11,882 clip이고 원음 replay는 별도로 고른 14개 원본 group(사건 13개, 배경 1개)이다. 두 표본 크기를 혼동하지 않는다.

## 정적 비교

사건 정답 출력률은 모든 실제 사건 clip 중 정답 라벨을 출력한 비율이다. 출력 정밀도는 출력한 사건 라벨 중 정답 비율이다. 배경 오출력률의 분모는 배경 clip이다.

| 조합 | 출력 정밀도 | 사건 정답 출력률 | 배경 오출력률 | macro F1 |
|---|---:|---:|---:|---:|
| F0/R0 | 82.30% | 79.00% | 14.56% | 0.7940 |
| F1/R0 | 83.19% | 84.24% | 17.69% | 0.8484 |
| F2/R0 | 83.72% | 84.84% | 17.33% | 0.8558 |
| F0/R1 | 95.00% | 57.58% | 4.69% | 0.6407 |
| F1/R1 | 94.98% | 68.55% | 6.43% | 0.7595 |
| F2/R1 | 94.70% | 70.16% | 6.61% | 0.7763 |
| F0/R2 | 88.55% | 67.03% | 11.08% | 0.7234 |
| F1/R2 | 89.53% | 74.58% | 10.72% | 0.8152 |
| F2/R2 | 89.35% | 75.64% | 10.99% | 0.8271 |

R0에서 F2는 F0보다 사건 정답 출력률이 5.84%p 높고 배경 오출력률도 2.77%p 높다. 성능 전반이 모두 개선된 것은 아니다.

### fire_alarm

F2에서 R0의 precision/recall은 50.14%/81.14%, R1은 53.50%/12.01%, R2는 51.18%/55.89%다. R1의 전체 정밀도만으로 채택하면 화재 경보를 많이 놓친다. R2는 recall을 지키려고 precision 목표를 완화한 결과이며, 라벨별 95% 정밀도 달성이 아니다.

### knock 보정 표본 공백

NPZ의 라벨별 분할을 직접 확인했다. knock은 fusion-fit 27 clip/3 group, policy-fit 0 clip/0 group, evaluation 99 clip/11 group이다. 임계값 진단의 `low_support_shared_unverified`와 일치한다. R2의 knock 성능은 라벨별 임계값을 충분히 보정한 성능으로 해석하면 안 된다.

현재 확대 실험은 seed 42와 기존 분할을 유지해 탐색 결과로 남긴다. replay 표본 확대만으로 policy-fit 공백이 해결되지는 않는다. 최종 R2 비교 전에는 별도의 보정 원본 확보와 라벨별 group 수를 고려한 분할 설계가 필요하다. 평가 결과가 좋아지는 seed를 고르는 방식은 사용하지 않는다.

## 원음 replay 비교

아래는 모두 R0/T0/wait_all/audio_clock이다. 정답·미검출의 기준은 실제 사건 onset이 아니라 음원 삽입 후 2초다. 첫 정답 시간 중앙값은 검출된 사건만 집계한다.

| 결합 | 판단 간격 | 2초 내 정답 | 2초 내 미검출 | 첫 정답 중앙값 | 잘못된 라벨이 한 번 이상 나온 사건 | 모델 호출 수 |
|---|---|---:|---:|---:|---:|---:|
| F0 | 2초 | 10/13 | 3 | 2.0초 | 1/13 | 126 |
| F0 | 1초 | 11/13 | 2 | 2.0초 | 2/13 | 210 |
| F0 | 0.5초 | 12/13 | 1 | 1.5초 | 3/13 | 378 |
| F1 | 2초 | 11/13 | 2 | 2.0초 | 1/13 | 126 |
| F1 | 1초 | 12/13 | 1 | 1.0초 | 3/13 | 210 |
| F1 | 0.5초 | 12/13 | 1 | 1.0초 | 4/13 | 378 |
| F2 | 2초 | 11/13 | 2 | 2.0초 | 1/13 | 126 |
| F2 | 1초 | 12/13 | 1 | 1.0초 | 2/13 | 210 |
| F2 | 0.5초 | 12/13 | 1 | 1.0초 | 4/13 | 378 |

F2의 1초 간격은 0.5초 간격과 이번 표본의 2초 내 정답 수 및 중앙값이 같고 호출 수가 44.4% 적다. 단, p95는 1초 간격 2.0초, 0.5초 간격 1.5초여서 느린 사례에는 0.5초 간격의 이점이 남는다.

정답 출력과 잘못된 라벨 출력은 한 episode에서 모두 발생할 수 있다. 잘못된 라벨 비율은 배경 오알림률과도 다르다.

- gun은 모든 조합에서 해당 원음 1개를 검출하지 못했다. gun 클래스 전체의 성능으로 일반화하지 않는다.
- F2/I1의 잘못된 라벨 episode는 baby_cry, bicycle이다. F2/I2에는 fire_alarm, glass_breaking도 추가됐다.
- 배경 1개에서 알림이 없었고 삽입 전 무음에서도 알림이 없었다. 이 표본으로 일반적인 배경 오알림률 0%를 주장하지 않는다.
- EfficientAT와 MobileNetV4는 RTX 4090, YAMNet은 CPU에서 실행됐다. audio_clock은 이 연산 시간을 제외하므로 실제 장치의 표시 지연이나 세 모델 동시 GPU 처리 지연이 아니다.
- 세 모델 cache는 각각 126 window × 14 class이고 runtime fingerprint가 scope와 일치한다. 세 분할 간 group 중복은 0이며 replay의 14 group은 모두 evaluation에 속한다.

## 다음 실행: 표본 확대와 R 비교

원본 결과를 보존하고 새 결과 폴더를 사용한다. 환경 재설치는 필요 없다.

### 1. 경로와 새 결과 폴더

```powershell
conda activate audio-policy
$pilotCode = "C:\Users\PLASS\Desktop\audio-policy-review-20261015T164106Z-1-001\audio-policy-review\audio_policy_pilot_v1_4"
$pilotProject = "C:\Users\PLASS\Desktop\audio_experiments_DEF"
$datasetRoot = "D:\Sound_Dataset_aug"
$pilotOut = Join-Path $pilotProject ("policy_results\V14_pilot_" + (Get-Date -Format "yyyyMMdd_HHmmss"))
Set-Location $pilotCode
Write-Output $pilotOut
```

새 터미널에서는 변수를 다시 지정하되 pilotOut은 위에서 기록한 기존 경로로 지정한다. 단계 중간에 timestamp를 다시 만들지 않는다.

### 2. 동일한 정적 정책 설정 생성

```powershell
python run_framework_pilot.py --project-root "$pilotProject" --assignment predefined --ratio 0.70 --seed 42 --fusions F0 F1 F2 --owner-background global_max --target-precision 0.95 --minimum-accepted 20 --recall-floor 0.5 --out "$pilotOut"
```

정책과 seed는 고정한다. 이 단계는 새 결과 폴더에 정책 설정을 생성하기 위해 반복한다.

### 3. 라벨당 최대 8개와 시작 위치 4종 준비

```powershell
python prepare_replay.py --selection --out "$pilotOut" --max-per-class 8 --phase-offsets 0 0.5 1 1.5 --seed 42 --old-dataset-root /home/plass/YAMNet/aug_data --dataset-root "$datasetRoot"
python check_replay_audio.py --out "$pilotOut"
```

모든 라벨에서 8개씩 선택되면 원본 group 112개, 합성 episode 448개, 모델당 4,704 window다. 시작 위치 반복을 원본 448개로 세지 않는다. audio_preflight.json의 passed=true, failed_files=0을 확인한다.

### 4. PyTorch 두 모델 재추론

```powershell
python export_replay_predictions.py --selection --project-root "$pilotProject" --out "$pilotOut" --model efficientat --device cuda
python export_replay_predictions.py --selection --project-root "$pilotProject" --out "$pilotOut" --model mobilenetv4 --device cuda
```

### 5. YAMNet 재추론

```powershell
conda activate audio-yamnet
python export_replay_predictions.py --selection --project-root "$pilotProject" --out "$pilotOut" --model yamnet --device cpu
```

세 replay_*.npz가 모두 새 결과 폴더에 생성돼야 한다. 작은 실행의 cache를 복사하지 않는다.

### 6. F × R × 고정 간격 27개 조합

```powershell
conda activate audio-policy
python evaluate_framework_replay.py --out "$pilotOut" --fusions F0 F1 F2 --rules R0 R1 R2 --inputs I0 I1 I2 --temporal T0 --timing audio_clock --async-policy wait_all --result-tag B_expanded
```

확인 파일: B_expanded_comparison.csv, B_expanded_per_episode.csv, B_expanded_trace.csv, B_expanded_scope.json 및 replay_manifest.json.

R별로 2초 내 정답 수, 미검출, 잘못된 라벨, 호출 수와 fire_alarm/gun/baby_cry/bicycle/knock 사례를 함께 확인한다. 현재의 작은 표본만 보고 F2나 1초 간격을 확정하지 않는다.

### 7. 동일 조건의 연산 시간 포함 모의 비교

```powershell
python evaluate_framework_replay.py --out "$pilotOut" --fusions F0 F1 F2 --rules R0 R1 R2 --inputs I0 I1 I2 --temporal T0 --timing independent_worker_sim --async-policy wait_all --result-tag B_expanded_fifo
```

추가 모델 추론 없이 같은 cache를 사용한다. 삽입 후 정확히 2.0초에 검출된 사례는 연산 시간을 포함하면 2초 기준을 넘을 수 있다. 이 모드는 단독 모델 서비스 시간으로 만든 독립 worker FIFO 모의실험이며 실제 동시 GPU/UI 측정은 아니다.

### 8. 다음 정책 비교 순서

확대 결과를 검토한 후 적응형 간격 I3, 시간 확인 T1/T2, bounded 대기를 각각 분리해서 비교한다. bounded는 F1/F2, 고정 I, T0에서만 가능하다. 모델 job을 취소하지 않으므로 추론량 감소라고 해석하지 않는다.
