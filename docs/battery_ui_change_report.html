기존 실시간 감지 화면의 구조와 색상 체계를 유지하면서, 라즈베리파이 기기에 연결된 배터리 잔량을 사용자가 즉시 확인할 수 있도록 연결 상태 칩의 정보 밀도를 확장했다. 데모 소리에도 가상 배터리 상태를 적용해 실제 기기 없이 정상·저전력 표현을 검토할 수 있다.

변경 요약

새로운 화면이나 별도 카드가 추가된 것이 아니라, 기존 홈 헤더의 우측 상태 칩을 재사용했다. 따라서 사용 흐름과 화면 높이는 그대로 유지되며 배터리 정보만 자연스럽게 추가된다.

01

기존 위치 재사용

홈 헤더 오른쪽의 연결 상태 칩 안에 배터리 아이콘과 잔량을 표시한다.

02

상태 기반 색상

정상 상태는 기존 브랜드 파랑, 20% 이하는 기존 위험 빨강을 사용한다.

03

기존 디자인 보존

화면 배치, 감지 애니메이션, 로그와 설정 구조에는 변화를 주지 않았다.

04

데모 상태 검증

개소리 76%, 위험음 15%를 표시해 정상과 저전력 디자인을 바로 비교한다.

홈 화면 전·후 비교

변경 전에는 연결 여부만 확인할 수 있었다. 변경 후에는 동일한 칩에서 배터리 아이콘과 백분율을 함께 보여주므로 별도의 화면 이동 없이 기기 전원 상태를 판단할 수 있다.

데모 소리의 가상 배터리 표시

데모 버튼은 실제 BLE 기기 상태를 변경하지 않고 홈 화면에만 가상 배터리를 표시한다. 개소리는 일반 배터리 상태를, 위험음은 저전력 경고 상태를 검토하도록 서로 다른 값을 사용한다.

정보 전달 흐름

일반 앱 실행과 Android foreground service 모두 같은 배터리 파싱 규칙을 사용한다. 앱이 백그라운드에 있어도 최신 배터리 값이 메인 화면의 기기 상태로 전달된다.

1

라즈베리파이

소리 분석 결과와 배터리 퍼센트를 JSON으로 생성한다.

2

BLE GATT notify

기존 characteristic 통로로 UTF-8 JSON을 전송한다.

3

DeviceStatus

값을 0~100 정수로 정규화하고 기기 상태 스트림으로 분리한다.

4

홈 상태 칩

연결 상태, 배터리 아이콘, 잔량 퍼센트를 즉시 갱신한다.

{
  "type": "sound_packet",
  "payload": {
    "status": "ok",
    "label": "dog_bark",
    "score": 0.92,
    "db": 58.4,
    "angle": 120,
    "battery": 82
  }
}

코드 변경 범위

UI 변경은 홈 헤더에만 제한했고, 데이터 수신은 기존 BLE 서비스와 foreground service의 책임 범위 안에서 처리했다. 데모 값은 MainPage에서 별도 상태로 관리한다.

lib/models/device_status.dart battery와 battery_percent를 지원하고 숫자·문자열 값을 0~100으로 정규화한다.
lib/ble/ble_sound_service.dart 별도 기기 상태 패킷과 소리 패킷 내부의 배터리 값을 모두 찾아 DeviceStatus로 전달한다.
lib/services/sound_foreground_task.dart 백그라운드 BLE 수신에서도 배터리 상태를 메인 isolate로 전달한다.
lib/main_page.dart 데모 전용 배터리 값을 관리하고 개소리 76%, 위험음 15%, 해제 조건을 정의한다.
lib/pages/home_page.dart 기존 상태 칩에 실제 또는 데모 배터리의 단계 아이콘, 퍼센트, 저전력 위험 색상을 적용한다.

기존 화면 구조 유지 홈 콘텐츠, 방향 표시, 감지 애니메이션, 로그와 설정 이동 구조는 변경하지 않았다.
데모 상태 분리 가상 배터리는 홈 데모에만 적용되며 실제 기기 상태와 설정 화면에는 반영되지 않는다.
APK 재빌드 필요 Gradle 빌드가 시간 초과되어 이번 변경이 반영된 APK는 아직 생성되지 않았다.
